## Goal
Prepare the Cloudflare Worker deployment path without weakening the rollout gate, without reusing the D1 provisioning token, and without performing any payment verification or settlement.

## Security decision
Cloudflare's current Wrangler/Workers authorization model distinguishes Worker deployment permissions from D1 resource permissions. The project therefore keeps the credentials separate:
- `CLOUDFLARE_D1_API_TOKEN` remains D1-only;
- Worker deployment requires a different secret, `CLOUDFLARE_WORKERS_API_TOKEN`;
- neither secret is stored in repository content or chat;
- `CLOUDFLARE_ACCOUNT_ID` may continue to be reused as the non-secret account selector.

The initial Workers token should use the smallest available deployment/edit permission. If the first real deploy proves that a stronger creation permission is required because the Worker does not yet exist, stop on that evidence rather than granting broader privilege in advance.
